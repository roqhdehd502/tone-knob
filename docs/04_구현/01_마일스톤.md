# 현재 아키텍처 요약

```
tone-knob/
├── frontend/               # React Router V7 (SSR) + React 19 + Tailwind v4 (유저 화면)
├── admin/                  # React Router V7 (SSR) + Tailwind v4 (관리자 패널, :3100)
├── backend/
│   ├── gateway/            # HTTP :3000 — API Gateway (Swagger, 인증, 프록시)
│   ├── auth-svc/           # TCP :3001 — 인증/사용자 관리
│   ├── tab-svc/            # TCP :3002 — 타브 CRUD, 포크, 퍼블리시
│   ├── jam-svc/            # TCP :3003 + WS :3004 — 합주/협업
│   ├── community-svc/      # TCP :3005 — 커뮤니티, 알림, 리뷰, 뱃지
│   ├── marketplace-svc/    # TCP :3006 — 마켓, 결제, 정산, Knob
│   ├── subscription-svc/   # TCP :3007 — 구독 플랜
│   ├── media-svc/          # TCP :3008 — 미디어 업로드/변환
│   └── ai-svc/             # TCP :3009 — AI 타브 생성/오디오 추출
├── packages/shared/        # 공유 DTO, 이벤트 상수 (@tone-knob/shared)
├── supabase/               # DB 마이그레이션 + 시드 데이터
└── docs/                   # 기획/분석/설계/구현 문서
```

- **DB**: Supabase PostgreSQL 17 (공유 DB, 서비스별 독립 커넥션 풀)
- **서비스 간 통신**: NestJS TCP (request-reply) + EventPattern (이벤트 드리븐)
- **인증**: JWT (access 15m, refresh 7d) + OAuth2 (Google, GitHub 조건부)
- **빌드**: Turborepo 모노레포

- [x] **구독 결제 위조 가능 (High, CWE-862)** — `subscription-svc`의 `subscribe()`가 클라이언트가 보낸 `externalPaymentId`를 검증 없이 그대로 신뢰해, 결제 없이 임의 문자열만으로 유료 플랜을 활성화할 수 있었음. `subscription.module.ts`에 `MARKETPLACE_SERVICE` TCP 클라이언트를 신설하고, `subscribe()`가 marketplace-svc의 `payment.getById`를 동기 호출해 결제 소유권·상태(completed)·종류(subscription)·금액 일치를 서버 측에서 재검증하도록 수정. 응답 지연 시 무한 대기하지 않도록 5초 타임아웃 적용. 동일 결제 건이 여러 구독에 재사용되는 것도 차단(재생 공격 방지).
- [x] **결제 확정 재생 공격 (Medium)** — `confirmPayment`/`confirmBillingKeyPayment`가 동일한 PortOne `externalPaymentId`를 서로 다른 내부 결제 레코드 2건에 중복 바인딩할 수 있었음(한 번의 실결제로 두 건을 completed 처리). 애플리케이션 레벨 중복 검사 추가 + DB 레벨 `UNIQUE INDEX`(`20240108000000_add_payment_external_id_unique_index.sql`, NULL 허용 partial unique index)로 동시 요청 경쟁 상태까지 차단. 실 DB에 적용 및 확인 완료.
- [x] **환불이 PG사에 실제로 반영되지 않음 (High)** — `refundPayment`가 내부 DB 상태만 `refunded`로 변경하고 PortOne에는 취소 요청을 보내지 않아, 사용자 카드/간편결제에서는 돈이 빠진 채로 남아있었음. `PortoneService.cancelPayment`(PortOne V2 결제 취소 API) 신설 후 환불 시 호출하도록 수정.
- [x] **웹훅이 confirm 전에 끊긴 결제를 영구히 놓침 (Medium)** — `handleWebhook`이 `externalPaymentId`(confirm 성공 후에만 저장됨)로만 결제를 조회해, confirm 호출 전에 브라우저가 꺼지는 등으로 끊긴 결제는 웹훅이 와도 영영 PENDING에 머물렀음. PortOne에 보낸 `paymentId`와 동일한 값인 `externalOrderId`도 함께 조회하도록 폴백 추가.
- [x] `marketplace-svc.controller.ts`의 `data as any` 타입 캐스트 제거 (정확한 `PaymentType` 타이핑으로 교체)
- [x] `payment.service.ts`의 `confirmPayment`/`confirmBillingKeyPayment` 중복 검증 로직을 `verifyAndLoadPendingPayment` 헬퍼로 통합
- [x] 마켓플레이스 탭 목록 진입 시 이미 구매한 탭의 구매 여부를 서버에서 조회하지 않아 새로고침 시 "구매하기" 버튼이 다시 노출되던 버그 수정 (`hasPurchased` 일괄 조회로 hydration 추가)

## 후속 작업으로 남겨둔 항목 (의도적으로 이번 범위에서 제외)

- [ ] **웹훅 서명 검증 미연결** — `PortoneService.verifyWebhookSignature`는 구현되어 있으나 `payment-proxy.controller.ts`의 웹훅 핸들러에 연결되어 있지 않음. 현재 `PORTONE_WEBHOOK_SECRET`이 비어있어 당장의 동작 변화는 없지만(미설정 시 검증 스킵), raw body 캡처 + PortOne의 정확한 서명 방식 확인 없이 임의로 연결하면 향후 시크릿 설정 시 모든 웹훅이 거부되는 회귀가 발생할 수 있어 보류함. 실 서비스 전환 전 PortOne 웹훅 서명 스펙을 확인한 뒤 연결 필요.
- [ ] **구독 자동 갱신 미구현** — `chargeSubscription`(빌링키로 서버 주도 청구) 인프라는 만들어졌으나 `SubscriptionExpiryScheduler`가 호출하지 않아, 구독은 매월 자동 갱신되지 않고 만료 시 free로 강등됨. 자동 갱신을 구현하려면 subscription-svc가 billingKey를 알아야 하는데 현재 billingKey는 marketplace-svc의 Payment 레코드에만 있어 추가 설계가 필요함.
- [ ] **구독 취소 시 빌링키 미파기** — `cancel()`이 PortOne에 저장된 빌링키를 삭제하지 않음(`PortoneService.deleteBillingKey` 호출처 없음). 자동 갱신이 구현되지 않은 현재는 실제 청구 위험은 없으나 PG사 측에 결제수단이 계속 남아있는 상태.

# Phase 15: OAuth 소셜 로그인 디버깅 및 보강 (완료)

> 2026-07-08 수행. Google/GitHub OAuth 아웃라인 구현 점검 후 발견된 버그 수정 및 누락 문서화.

## 발견 및 수정한 버그

- [x] **GitHub 비공개 이메일 → DB 충돌 (Bug)** — `passport-github2` 는 이메일 비공개 설정 사용자에게 빈 배열을 반환. 기존 코드의 `?? ""` 폴백으로 인해 email 컬럼이 빈 문자열(`""`)로 저장되어 UNIQUE 제약 충돌 또는 인증 불가 상태가 발생할 수 있었음. `github.strategy.ts`에서 `${profile.id}@users.noreply.github.com` 형식의 noreply 주소로 대체하도록 수정
- [x] **OAuth 콜백 에러 핸들링 누락 (Bug)** — `googleCallback`·`githubCallback` 에서 `auth-svc` 마이크로서비스 호출이 실패(서비스 다운, DB 오류 등)하면 unhandled exception이 발생해 브라우저에 500 에러 페이지가 노출되었음. try-catch를 추가하고 에러 시 `${FRONTEND_URL}/login?error=social_auth_failed` 로 리다이렉트하도록 수정
- [x] **setSocialTokens race condition (Bug)** — `auth-callback.tsx` 에서 `setSocialTokens`(`void refreshUser()` 후 즉시 반환)를 호출한 직후 `navigate("/")` 가 실행되어, 홈 화면에 진입할 때 `user` 가 잠시 `null` 인 상태(깜박임)가 발생했음. `setSocialTokens` 를 `async/await` 으로 변경하고 `navigate` 는 `refreshUser` 완료 후 호출하도록 수정. `refreshUser` 가 실패해 토큰이 지워진 경우에는 `/login?error=auth_failed` 로 리다이렉트
- [x] **login.tsx OAuth 에러 미표시 (Bug)** — OAuth 콜백 실패 후 `/login?error=...` 로 리다이렉트되어도 에러 메시지가 전혀 표시되지 않았음. `useSearchParams`로 `error` 쿼리 파라미터를 읽어 에러 배너를 표시하도록 수정
- [x] **gateway `.env.sample` OAuth 키 누락 (Docs)** — `GOOGLE_CLIENT_ID/SECRET`, `GITHUB_CLIENT_ID/SECRET`, `*_CALLBACK_URL` 6개 항목이 `.env.sample` 에 없어 OAuth 설정 방법을 알 수 없었음. 발급처 안내 주석과 함께 플레이스홀더 추가

## 환경변수 발급 가이드 (gateway/.env)

### Google OAuth2

1. [Google Cloud Console](https://console.cloud.google.com) → 프로젝트 선택 또는 신규 생성
2. **APIs & Services → Credentials → + CREATE CREDENTIALS → OAuth client ID**
3. Application type: **Web application**
4. Authorized redirect URIs: `http://localhost:3000/api/auth/google/callback`
   - 프로덕션: `https://api.yourdomain.com/api/auth/google/callback`
5. 발급된 `Client ID` → `GOOGLE_CLIENT_ID`, `Client Secret` → `GOOGLE_CLIENT_SECRET`

### GitHub OAuth2

1. GitHub → **Settings → Developer settings → OAuth Apps → New OAuth App**
2. Homepage URL: `http://localhost:5173`
3. Authorization callback URL: `http://localhost:3000/api/auth/github/callback`
   - 프로덕션: `https://api.yourdomain.com/api/auth/github/callback`
4. Register application 후 **Generate a new client secret**
5. `Client ID` → `GITHUB_CLIENT_ID`, 생성된 Secret → `GITHUB_CLIENT_SECRET`

> **주의**: 키를 미설정하면 해당 Provider OAuth 전략이 자동 비활성화됨 (`auth-proxy.module.ts` 조건부 등록). 버튼을 클릭하면 Passport가 전략을 찾지 못해 500 에러가 발생하므로, 미설정 시 로그인 UI에서 버튼을 숨기는 것을 권장함.

## 사용자 측 조치 필요 사항

> 아래 항목은 코드 수정 없이 PortOne 콘솔에서 값을 발급받아 `.env`에 반영해야 합니다.

### PORTONE_STORE_ID 재발급 필요

현재 `.env`의 `PORTONE_STORE_ID`는 **PortOne V1** 가맹점 식별코드 형식입니다. PortOne V2 SDK(`@portone/browser-sdk/v2`)는 V2 Store ID를 요구하며, 이 값이 잘못되면 `requestIssueBillingKey` 호출 시 즉시 실패합니다.

**발급 방법**:

1. [PortOne 콘솔](https://admin.portone.io) 로그인
2. 좌측 메뉴 **내 식별코드 · API Keys** (또는 **Store 관리**)
3. V2 API 섹션의 **Store ID** 복사 (형식: `store-XXXXXXXX`)
4. `backend/marketplace-svc/.env` 및 `backend/gateway/.env`의 `PORTONE_STORE_ID` 교체

### PORTONE_CHANNEL_KEY 확인

채널키(`PORTONE_CHANNEL_KEY`)는 PortOne 콘솔 → **결제 연동 → 채널 관리**에서 테스트/실결제 채널별로 발급됩니다. 현재 값이 V2 테스트 채널의 키인지 확인 필요.

### PORTONE_WEBHOOK_SECRET 설정 (선택)

현재 비어 있어 웹훅 서명 검증이 비활성화된 상태입니다. 실 서비스 전환 전 PortOne 콘솔에서 웹훅 시크릿을 발급받고 `.env`에 반영 후 `verifyWebhookSignature` 연결 필요 (Phase 10 후속 항목).
