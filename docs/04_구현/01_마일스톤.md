# 현재 아키텍처 요약

```
tone-knob/
├── frontend/               # React Router V7 (SSR) + React 19 + Tailwind v4
├── services/
│   ├── gateway/            # HTTP :3000 — API Gateway (Swagger, 인증, 프록시)
│   ├── auth-svc/           # TCP :3001 — 인증/사용자 관리
│   ├── tab-svc/            # TCP :3002 — 타브 CRUD, 포크, 퍼블리시
│   ├── jam-svc/            # TCP :3003 + WS :3004 — 합주/협업
│   ├── community-svc/      # TCP :3005 — 커뮤니티, 알림, 리뷰, 뱃지
│   ├── marketplace-svc/    # TCP :3006 — 마켓, 결제, 정산, Knob
│   ├── subscription-svc/   # TCP :3007 — 구독 플랜
│   ├── media-svc/          # TCP :3008 — 미디어 업로드/변환
│   └── ai-svc/             # TCP :3009 — AI 타브 생성/오디오 추출
├── packages/shared/        # 공유 DTO, 이벤트 상수 (@tone-knob/shared)
├── supabase/               # DB 마이그레이션 + 시드 데이터
└── docs/                   # 기획/분석/설계/구현 문서
```

- **DB**: Supabase PostgreSQL 17 (공유 DB, 서비스별 독립 커넥션 풀)
- **서비스 간 통신**: NestJS TCP (request-reply) + EventPattern (이벤트 드리븐)
- **인증**: JWT (access 15m, refresh 7d) + OAuth2 (Google, GitHub 조건부)
- **빌드**: Turborepo 모노레포

- [x] 접근성(A11y) 개선 — 전역 헤더/사이드바(모든 페이지에서 공유) 위주로 개선: 아이콘 전용 버튼(메뉴/알림/로그아웃) `aria-label` 추가, 검색 입력창 `aria-label` 추가, 사이드바에 `aria-label` 랜드마크 + 모바일 오버레이 `aria-hidden` + Esc 키로 닫기 추가. `<img>` alt 누락은 전수 점검 결과 이미 모두 적용되어 있음을 확인. 라우트별 세부 폼/위젯 단위 전수 감사는 범위 밖(향후 추가 개선 필요)

### 인프라/운영

- [x] MSA 서비스별 독립 Docker 이미지 + Kubernetes 매니페스트 — Docker 이미지는 9개 서비스 모두 기존에 이미 구비(`services/*/Dockerfile`). `k8s/` 디렉토리에 Namespace/ConfigMap/Secret/Redis + 9개 서비스 Deployment·Service + Ingress 신규 작성. 정산/구독만료 크론을 가진 marketplace-svc·subscription-svc는 중복 실행 방지를 위해 replicas:1로 고정, jam-svc의 Socket.IO(3004)는 Ingress에서 경로 기반으로 gateway(REST)와 분리 라우팅. `kubectl --dry-run`은 로컬에 클러스터가 없어 실행 불가했으나 js-yaml로 14개 파일 전체 YAML 구조(apiVersion/kind/metadata.name) 검증 완료
- [x] 로그 수집 및 모니터링 (Sentry) — Gateway(`@sentry/nestjs`, instrument.ts 사전 초기화 + 기존 `RpcToHttpExceptionFilter`에서 5xx만 캡처)와 프론트엔드(`@sentry/react`, root.tsx/MainLayout.tsx ErrorBoundary에서 캡처)에 연동. **블로커**: 실제 Sentry DSN이 없어 종단 간 전송은 검증 불가 — `SENTRY_DSN`/`VITE_SENTRY_DSN` 미설정 시 SDK가 자동 비활성화되어 기존 동작에는 영향 없음. 나머지 8개 마이크로서비스는 동일 패턴(instrument.ts + 필터)으로 복제 가능
- [x] 서비스 디스커버리 / 컨피그 서버 (프로덕션 대비) — 전용 레지스트리(Consul/Eureka) 대신 환경별 기존 메커니즘에 위임하는 정적 디스커버리로 설계 확정: 로컬은 `.env` host/port, Docker Compose는 컨테이너명 DNS, **Kubernetes는 Service DNS + ConfigMap/Secret을 컨피그 서버로 활용**, 서버리스는 배포 시점 고정 URL. 근거와 전환 조건은 `docs/04_구현/02_MSA아키텍처.md` §9.4에 문서화
- [x] Rate Limiting (Gateway 레벨) — `@nestjs/throttler` 전역 가드(60req/min)가 이미 적용되어 있었음(문서 누락 발견, 체크 반영). 추가로 회원가입/로그인/토큰갱신에 브루트포스 방어용 엄격한 제한(`@Throttle` 10~20req/min) 신규 적용
- [x] E2E 테스트 (MSA 환경 Playwright 통합) — `playwright.config.ts`의 `webServer`를 배열로 확장해 프론트엔드뿐 아니라 `npm run dev:services`(Gateway+9개 마이크로서비스)도 함께 기동하도록 변경. 회원가입→로그인→프로필 확인까지 실제 백엔드 왕복을 검증하는 `e2e/registration-flow.spec.ts` 신규 작성. **블로커**: 로컬에 `DATABASE_URL`(Supabase Postgres) 자격증명이 없어 실제 실행/통과 확인은 불가 — 기존 3개 spec 파일은 백엔드 없이도 통과 가능한 라우팅/리다이렉트 테스트라 영향 없음. 부수적으로 e2e/ 전체 파일의 기존 lint 스타일(따옴표/import 정렬) 정리
- [x] 프론트엔드 / 백엔드에 대한 배포 셋업 — 프론트엔드는 기존 `frontend/vercel.json`(Vercel 정적 배포)으로 충분함을 확인. 백엔드는 원안(Vercel 서버리스, MSA아키텍처.md §9.1~9.3)이 8개 서비스가 전부 TCP 마이크로서비스(HTTP 어댑터 없음)라 그대로는 적용 불가능함을 발견 — Fly.io 단일 플랫폼으로 변경 확정(기존 Dockerfile/TCP 구조 무변경, 프라이빗 네트워킹으로 인터-서비스 통신). 9개 서비스 전체에 `services/*/fly.toml` 신규 작성(TOML 문법 검증 완료). **블로커**: 실제 Fly.io/Vercel 계정이 없어 `fly deploy`/`vercel` 실행 결과는 검증 불가
